# Contributing

[简体中文](CONTRIBUTING.zh-Hans.md)

## Requirements

- macOS 12 or later
- Xcode Command Line Tools (`xcode-select --install`); a full Xcode installation is not needed
- Python 3, which ships with the Command Line Tools, for the localization check
- Optional: [ripgrep](https://github.com/BurntSushi/ripgrep) (`rg`), used for workspace content search when available

## Common tasks

```bash
make            # build build/FeatherView.app for the host architecture, ad-hoc signed
make run        # build and open with the current directory as the workspace
make test       # localization check, logic tests, Markdown tests, live-view tests
make install    # install to /Applications (or ~/Applications if that is not writable)
make release    # run the tests, then build a universal (arm64 + x86_64) package in dist/
scripts/bench.sh 3 20 > results.tsv   # resource comparison with VS Code, Zed and Chrome
```

## Conventions

- **Style.** Follow the surrounding code: ARC, four-space indentation, `static` C functions for pure computation, and comments only for constraints the code cannot express.
- **Tests.** Every feature and fix comes with a test. User-interface behaviour belongs in `tests/editor_tests.m`, which drives real views in an offscreen window; pure logic belongs in `tests/tests.m`.
- **User data.** Tests must never touch the user's data. Use `[NSPasteboard pasteboardWithUniqueName]` instead of the general pasteboard, the injectable trash handler instead of the real Trash, and temporary directories for files. Name fake application bundles with the `.testapp` extension, because Launch Services registers `.app` bundles automatically.
- **Default apps.** FeatherView must never make itself the default for a file type. Every document type in `Info.plist` must use `LSHandlerRank None`; the list is generated by `scripts/gen_doc_types.py` and checked by the tests.
- **Memory.** Measure memory with `footprint` (`phys_footprint`, the Memory column in Activity Monitor), not RSS.
- **Performance.** When changing performance-sensitive code (drawing, soft wrap, search, large files), compare the timings that `make test` prints.

## User interface text

English is the development language, and the English text is the key.

1. Wrap every user-visible string in `FTL(@"…")`. Use title case for menu items and buttons, and sentence case for labels, hints and messages, following the macOS Human Interface Guidelines.
2. For text containing a count, use `FTLP(count, @"%lu file", @"%lu files")`. English uses the first form for exactly one.
3. Add the translation to `Resources/zh-Hans.lproj/Localizable.strings`. `scripts/l10n.py --missing` prints the keys that still need a translation, as ready-to-fill `.strings` lines.
4. Keep the format specifiers of the key and the translation identical. Use positional specifiers (`%1$@`, `%2$@`) when the languages order the arguments differently.
5. Run `make test`. `scripts/l10n.py` fails on missing or unused translations, mismatched specifiers, and Chinese text in the sources outside the string tables.

To add a language, create `Resources/<lang>.lproj/Localizable.strings` and `InfoPlist.strings`, add the language code to `CFBundleLocalizations` in `Info.plist`, and run `make test`.

## Releases

1. Update `CFBundleShortVersionString` and `CFBundleVersion` in `Info.plist`, and add an entry to `CHANGELOG.md`.
2. Run `make release` to produce `dist/FeatherView-<version>-macos-universal.zip` and its `.sha256` file.
3. Tag the commit as `v<version>` and upload both files with `gh release create`.
