# Architecture

[简体中文](architecture.zh-Hans.md)

FeatherView is an Objective-C application built on AppKit. It has no third-party dependencies and is built by `make`, which invokes clang directly. One goal drives the design: **provide viewing and light editing in a single native process with as little memory as possible.** The decisions below follow from it.

## Source layout

```
src/
  Support/   Localization (FTL / FTLP), FTSplitView, FTTabDrag and FTTabDropView
  App/       Entry point, window, menus, tab and document management (ContentController), settings,
             welcome page, default-app selection
  Editor/    Text editor: PieceTable buffer; TextEditorView (drawing, input, soft wrap, minimap, search);
             syntax highlighting; tab bar
  Files/     File tree, directory traversal and filtering, file operations, type detection, file icons
  Search/    Workspace search (ripgrep or a built-in walker), search panel, Quick Open
  Preview/   Markdown parser and native renderer, HTML preview, table, tree and notebook views and their models
  Viewers/   Image, SVG, PDF, hex, SQLite and archive viewers
  Terminal/  TSession (PTY and lifecycle), VTEscape, TScreen, TerminalView and TerminalPanel
Resources/   <lang>.lproj string tables
tests/       Nine test programs: Foundation-only logic, Markdown parsing, terminal core, editing commands,
             live views, application terminal lifecycle, terminal input routing, file tree/sidebar and tab dragging
tools/       Application icon, drawn in code
scripts/     Installation, release packaging, benchmark, localization check, Info.plist document types
docs/        This document and the benchmark
```

Modules include each other's headers directly. The Makefile adds an `-I` flag for every module, so `#import "FileKind.h"` needs no path.

## Design decisions

**The editor does not use NSTextView.** `TextEditorView` is a self-scrolling `CanvasView` that lays out only the visible lines with CoreText on each frame. Text is stored in a `PieceTable`: the original file is memory-mapped rather than copied, edits are appended to an add buffer, and a table of line-start offsets is maintained alongside. Opening a 100 MB log therefore costs about the same memory as opening a 1 KB file; see the [benchmark](benchmark.md).

**Soft wrap uses prefix sums.** When wrapping is on, `_rowStart[L]` holds the first visual row of logical line L. Converting between lines and rows is a binary search, and an edit re-measures only the lines it touched before shifting the rest, which costs about 0.04 ms per keystroke in a 100,000-line file. The break rules — after spaces and after characters such as `-`, `/` and `,`; between CJK characters; never placing `，` or `。` at the start of a row; indenting continuation rows like their line — live in a single function, `rowsOf:width:`. Table construction, drawing, hit testing and caret movement all share it, so what is drawn and what is clicked cannot disagree. When the width changes, the table is rebuilt with the logical line at the top of the view as the anchor, so the content does not jump.

**Markdown is rendered natively; only HTML uses WebKit.** A WKWebView starts three helper processes (GPU, WebContent and Networking), measured at about 70 MB, which remain until the application quits. Markdown is therefore converted by FeatherView's own parser into TextKit attributed text, and a WebView is created only when an `.html` file is actually opened. Sessions that never display HTML never pay for it.

**Fresh previews wait for real layout.** `MarkdownPreview` and `PDFPreview` hold a one-shot initial-position request until they are mounted with usable geometry. Markdown establishes TextKit layout before scrolling to the document origin; PDFKit converts the displayed top of page 1 back into page coordinates, accounting for crop origins and rotation. Explicit anchors, source/page navigation and find results take precedence. Once consumed or superseded, the request is not reapplied on resize or focus changes.

**Data views parse on demand.** CSV cells are stored as byte ranges (arrays of `uint32`) rather than as one string per cell. JSON is read by FeatherView's own parser, which preserves key order and line numbers so that "Show in Source" can jump to the right place. SQLite files are opened read-only and queried in pages. Archives are listed with the system `bsdtar`.

**Hostile input is bounded.** Files are often generated by tools or come from elsewhere, so every parser has a ceiling instead of trusting its input: Markdown nesting stops at 48 block levels and 32 inline levels, and emphasis is matched with cmark's linear "openers bottom" algorithm; JSON and property lists stop at 2 million nodes (a binary plist can describe an exponentially large tree in a few hundred bytes); a table shows at most 1,000 columns; a regular expression gives up on a line after 2 seconds. `tests/markdown_tests.m` and `tests/tests.m` time the pathological cases.

**Saving never loses the original.** `save:` writes a temporary file in the same folder, copies the original's mode, extended attributes and ACLs to it, and renames it over the original, so a failed write leaves the file intact and the memory-mapped buffer stays valid. Two cases write in place instead: a file with other hard links, and a writable file in a read-only folder; both only for files small enough to have been read into memory. Read-only files are refused. Replace All builds the new text in one pass and swaps the buffer, and undo swaps it back.

**Multiple cursors are one change, not many.** The primary cursor is the editor's `_anchor` / `_caret`, so input methods, VoiceOver and find keep their single-cursor view; the others are a sorted array kept free of overlaps. Every command produces a list of replacements (`EditList`), which `PieceTable applyEdits:` applies in a single pass over the pieces and line starts, and the wrap table is updated in one pass that re-measures only the touched lines. The undo record is one batch per change, with the cursors before and after; consecutive keystrokes are merged into the same batch, so typing a word at 10,000 cursors is one undo step of 10,000 edits rather than 70,000. Piece lookups use a binary search over piece offsets, since many cursors leave many pieces.

**The terminal is a PTY, a parser and a grid.** `TSession` runs the login shell on a pseudo-terminal; a serial queue handles I/O and the main thread parses bounded chunks. `VTEscape` drives `TScreen` through CSI, OSC, DEC private modes and UTF-8 across feed boundaries. The grid has deferred autowrap, an alternate screen and 5,000 lines of scrollback. Every screen initializes ANSI 16-color and xterm 256-color palettes; each view applies the appearance's first 16 colors. Truecolor RGB black remains distinct from the default-color sentinel. Resize preserves content without reflow: full-screen scrolling follows the new height, explicit margins are clamped and restored, and shrinking removes unused bottom space before moving rows above the cursor into history. Growing can bring history back into the grid.

**One terminal session reuses one view across placements.** `ContentController` keeps the canonical session-to-`TerminalView` cache and supplies it to `TerminalPanel` through `viewProvider`. The same view moves between editor tabs and panel columns, preserving viewport, selection and follow intent alongside the session's PTY and scrollback. Hidden, detached or unusably small geometry does not resize the PTY. A logical history anchor keeps the reading position while output arrives; scrolling upward pauses follow mode until the viewport returns to the bottom. `TerminalView` draws with CoreText, forwards keys and mouse events, and hosts the input method at the cursor. The terminal core remains Foundation-only, so `build/terminal_tests` can drive a real shell without AppKit.

**Terminal controls precede text input handling.** `TerminalView` handles native key equivalents and encodes standard terminal controls before passing ordinary text to `inputContext`. ⌃C emits the interrupt byte even with selected text; ⌃R and ⌃G take priority over the Switch Workspace and Go to Line menu shortcuts while the terminal has focus. ⌘ commands retain menu routing, and marked-text composition and navigation remain with the input method.

**Terminal lifetime outlasts UI ownership.** `TSession.liveSessions` strongly retains unfinished sessions, including closing sessions no longer owned by a tab or panel. Records contain application and UID markers plus kernel process identities for the owner, shell and tracked jobs: PID, birth time, UID, executable, session and process group. The asynchronous orphan sweep requires a provably dead recorded owner and revalidates exact identities before signaling. A live or unverifiable owner, reused PID or unverifiable legacy record cannot authorize a signal; legacy records are retired without killing by shell name. PTY descriptors are close-on-exec, and shell spawning closes unrelated inherited descriptors.

Termination is idempotent: verified session members and descendants receive HUP, then surviving verified jobs receive KILL after a grace period. Completion requires the child to be reaped, PTY EOF and all buffered output parsed, descriptors closed and tracked jobs cleaned up. Shell exit alone cannot discard the final output tail. `shutdownAllSessionsWithTimeout:` pumps the run loop; a timeout leaves unfinished sessions and records retained. Application quit uses `NSTerminateLater` and replies only after cleanup completes. This recovery policy covers verifiable application records, not every shell process left on the machine.

**Folded lines have no rows.** Folding reuses the soft-wrap row table: a hidden line counts zero rows, so drawing, hit testing and moving up and down skip it without knowing about folds, and the table stays in use while anything is folded even with wrapping off. Before an edit each fold is turned into two offsets (the end of its first line and of its last hidden line), moved by the edits before them, and turned back into lines afterwards; an edit that reaches into the hidden lines drops the fold, and the incremental row update then gives way to a rebuild.

**Split view keeps editor and terminal groups independent.** Each `FTSplitView` holds up to three child views and remembers normalized manual widths by item identity. Its `maximized` expansion flag defaults to off independently per area. Double-clicking a tab or pressing ⌃⌘M toggles expansion for that area; an editor preview tab is still pinned by the double-click. While enabled, expansion follows focus without changing group order; sibling groups retain a 180 pt minimum, reduced to an equal share only when space is insufficient. Toggling off restores the stored manual weights. Divider hit testing takes priority over children; dragging disables expansion and stores the chosen proportions across resizes. Focus never re-enables expansion, even for a group at its minimum width. Reducing the area to one or zero children resets expansion to off.

Each editor `PaneView` owns its tab strip, find bar and active content. Identity-based callbacks, `_paneActive` and `Doc.pane` reindexing keep viewers mounted on focus changes and retain surviving tabs when a left or middle column is removed. `FTTabDrag` uses a process-local token and a main-window mouse-event session. Tab strips show insertion lines for moving and reordering; body edges show a half-body split preview and the center shows a merge preview. Target discovery uses visible view geometry, so HTML and terminal child views cannot consume the gesture, and no drag view is inserted into the outer `NSSplitView`. Headers and find bars stay outside the blue preview; Escape, application deactivation and window closing cancel safely. Empty source columns are removed and editor column assignments are saved with the session. `TerminalColumnState` independently owns a host and session tabs, and the panel obtains each canonical view from the controller. A regular new terminal adds a tab to the current column; the three-column limit does not limit session count.

**The sidebar hides as one unit.** `AppDelegate` keeps the entire Files/Search sidebar in the outer `NSSplitView`. The title-bar button and ⌘B hide or show it, retaining its previous width within the available window space. File Tree (⇧⌘E) and workspace search (⇧⌘F) reveal it and select the corresponding tab. `FileTree` owns the native **Collapse All** text button above the outline; recursive collapse suppresses selection callbacks so hiding nested rows cannot reopen folders or replace the active document. It leaves open documents intact.

**The workspace is watched with FSEvents.** `FileWatcher` reports changes under the workspace folder, coalesced over half a second and ignoring skipped folders such as `.git` and `node_modules`. The tree then re-reads the folders it has already shown on a background queue and reloads only if a listing changed.

**Workbooks are edited by splicing, not rewriting.** An .xlsx is a zip of XML parts. `ZipArchive` copies every entry it doesn't change byte for byte, compressed data included. While reading a worksheet, `XLWorkbook` records the byte range of every cell element; saving replaces only the edited cells' ranges (or inserts new elements in order), sets `fullCalcOnLoad` so Excel and Numbers recalculate, and drops the optional calculation chain. Charts, pivot tables, macros, comments and formatting rules are therefore never touched. The result is parsed again before it replaces the file. Word documents are only displayed: the system's Office converter (the one Quick Look uses) produces HTML that is shown in a web view with scripts disabled, because no converter available on macOS can save a .docx without losing content.

**Images are decoded at display size.** ImageIO decodes only the pixels needed for the current zoom level and decodes again when zooming in, up to 24 megapixels.

**Default apps are never taken over.** Every document type in `Info.plist` uses `LSHandlerRank None`. After installation FeatherView appears under "Open With" but never becomes the default for any file type on its own; a default changes only when the user selects it in the Default Apps panel. `tests/tests.m` verifies this.

**User interface text is localized.** English is the development language, and the English text itself is the key: `FTL(@"Save All")`. Count-dependent text uses `FTLP(n, @"%lu file", @"%lu files")`, which selects the singular form for exactly one in English. Translations live in `Resources/<lang>.lproj/Localizable.strings`; macOS chooses the language from the user's preferred-language order (Simplified Chinese for `zh-Hans`, English otherwise). `scripts/l10n.py` runs as part of `make test` and fails if a key lacks a translation, if format specifiers differ between a key and its translation, if a translation is unused, or if Chinese text appears in the sources outside the string tables.

## Tests

```bash
make test
```

- `scripts/l10n.py`: translation coverage and format-specifier consistency.
- `build/tests`: logic tests for the piece table, traversal and filtering, search options, and CSV, JSON and notebook parsing.
- `build/markdown_tests`: 91 Markdown cases, including front matter, CommonMark examples for emphasis and links, time limits for pathological input, and nesting caps.
- `build/terminal_tests`: escape parsing into a grid (colors, regions, alternate screen, wide chars, UTF-8 recovery), random-byte fuzzing with a time bound, and a real `/bin/sh` on a PTY (echo, exit codes, a 20,000-line dump, termination).
- `build/editing_tests`: multiple cursors, line commands and typing aids, written as text with the cursors marked in it (`"a|b\nc[d|]"`), plus a fuzz test of the wrap table under multi-cursor edits and a 10,000-cursor timing. Split coverage includes default-off expansion, independent tab double-click toggles, divider drags and manual-width restoration, focus changes that retain manual widths, and saved editor column assignments.
- `build/editor_tests`: drives the real editor, file tree, tabs, previews and viewers in an offscreen window, checking behaviour, pixels and performance — for example, "a minimap frame on a 100,000-line file takes under 16 ms" and "after every edit, the incrementally maintained wrap table equals a full rebuild". It also checks first-layout Markdown/PDF positioning and navigation precedence, viewer retention across split focus/removal, and menus and status bars in both languages.
- `build/session_lifecycle_tests`: application-level terminal teardown after tabs lose their UI owners, window close with terminal tabs and panel sessions, and quit with a shell that ignores HUP; checks reaping, output drain and the global live-session registry.
- `build/terminal_input_tests`: native AppKit key routing, standard control and navigation sequences, ⌃R/⌃G menu conflicts, ⌘C selection behavior and IME commits; isolated real PTYs check exact bytes, ⌃C interrupt, ⌃D EOF and ⌃Z suspend behavior.
- `build/file_tree_tests`: native folder and disclosure clicks, recursive Collapse All without changing open documents or unsaved edits, refresh after collapse, sidebar hide/show and width restoration, Files/Search reveal, and empty roots.
- `build/tab_drag_tests`: queued mouse-event tests through the real main window for editor/terminal reordering, splitting, merging, panel/editor migration, HTML previews, cancellation, half-body preview geometry and stable window layout; verifies the original PTY still executes after moving.

`make sanitize` builds and runs all nine test programs with AddressSanitizer and UndefinedBehaviorSanitizer; `make analyze` runs the clang static analyzer and fails on any finding.

Tests use private pasteboards, an injectable trash handler and temporary directories instead of the user's clipboard, Trash, untitled-document backups or real settings. Terminal spawning and orphan-recovery tests must set `FEATHERVIEW_TERMINAL_PIDS_DIR` to an isolated absolute directory before creating or sweeping sessions.
